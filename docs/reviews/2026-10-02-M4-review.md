## 🔴 BLOCKERS

### B-01 · DECIMAL(12,2) used instead of NUMERIC(12,2) in DDL migrations

**Files:**
- `database/migrations/P04-M04-T01-01_create_service_catalogue.sql` line 8: `DECIMAL(12,2)`
- `database/migrations/P04-M04-T03-01_create_service_usage.sql` line 15: `DECIMAL(12,2)`

**Rule violated:** AGENTS.md §8 — "Money: always NUMERIC(12,2), never FLOAT or DOUBLE PRECISION"

DECIMAL is an alias for NUMERIC in PostgreSQL and numerically identical, but the project contract mandates `NUMERIC(12,2)` explicitly for consistency and clarity. All other money columns in the project use `NUMERIC(12,2)`.

Additionally: `usage_date TIMESTAMP` lacks timezone — AGENTS.md §8 mandates `TIMESTAMP WITH TIME ZONE` for event timestamps.

**FIX APPLIED:**
- `current_price DECIMAL(12,2)` → `NUMERIC(12,2)` in service_catalogue.sql
- `charged_price DECIMAL(12,2)` → `NUMERIC(12,2)` in service_usage.sql
- `usage_date TIMESTAMP` → `TIMESTAMP WITH TIME ZONE` in service_usage.sql

### B-02 · Checkin and services routes use hardcoded getDevSession() — iron-session never called

**Files:**
- `app/api/staff/reservations/[id]/checkin/route.ts` line 72: `const session = getDevSession();`
- `app/api/staff/reservations/[id]/services/route.ts` line 116: `const session = getDevSession();`
- `app/api/staff/services/route.ts` lines 112, 133: `const session = getDevSession();`

**Rule violated:** AGENTS.md §10 — "Never trust a browser-supplied guest_id or role as authorization. Read role and branch scope from the authenticated server-side session."

These three routes bypass the session system entirely even when cookies are present. A real user would always get the dev stub session regardless of their actual iron-session cookie. This means role enforcement is entirely mocked — any request hits the dev fallback `Receptionist` session.

In contrast, the M5 routes (checkout, payments, billing) correctly try `getSession()` first and fall back to dev stub only in non-production.

**FIX APPLIED:** Added `getSession()` import and `resolveSession()` wrapper to all three routes. Also split combined `!userId || !isStaffRole(role)` check into proper 401 (unauthenticated) and 403 (wrong role) responses.

### M-01 · service-usage repository: line_total computed in TypeScript (line 226)

```ts
line_total: (parseFloat(u.charged_price) * u.quantity).toFixed(2),
```

This is explicitly called out in the comment as a mock-only display computation. The authoritative total is `fn_calc_service_charges()` in PostgreSQL. The comment on line 225 says:
> "line_total mirrors vw_service_usage_breakdown: charged_price * quantity"

This is acceptable in mock phase — it mirrors what the DB view will compute. It must NOT be used as an authoritative total. Phase 6 swap to `vw_service_usage_breakdown` eliminates this code path.

**Status:** ACCEPTED for mock-first phase.
